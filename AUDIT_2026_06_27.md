# AUDIT 2026-06-27 — Code audit + audit-of-the-audit

Four parallel auditors: domain coverage, code wiring, meta-audit, submission risk.
Baseline at audit time: tsc 0 errors · jest 112 suites / 2680 passed · HEAD 8da90a25.

## Bottom line

The app is **well-built but not verified-correct**. The audit process to date proves
the code compiles, wires up, doesn't overlap on screen, and won't crash on launch.
It has **never** verified the three things the mission actually rests on:
1. that the regulation **data is factually correct** (it has real legal errors — see below),
2. that the app works **offline with the radio off** (backend was silently dead ~6 weeks; no audit noticed),
3. that a **brand-new / real-device** user gets a working first run.

## 🔴 Mission-critical content errors — FIXED THIS SESSION

sources, and locked with `src/data/__tests__/huntRegsAccuracy.test.ts` (10 guards).

1. **Region A vs Region B deer framework MISSING + FABRICATED.** MD deer hunting is defined
   by two regions (A = western: Garrett/Allegany/Washington/Frederick; B = rest) with

   counties. Telling a Region A hunter "5 antlerless/year" is **over the legal limit**.
2. **Sunday hunting modeled as a boolean** — it is county + specific-date (DNR Sunday Deer
   Hunting Calendar). App green-lights illegal Sundays.
3. **Legal shooting hours missing** for deer/turkey/small game (only one waterfowl line exists).
4. **Blaze orange law missing** from the regs layer (only in gear marketing copy).
5. **Field-tagging procedure missing** entirely.
6. **"Can I Hunt?" checker ignores county** — `isInSeason()` never filters on county, returns
   "IN SEASON" for bear/grouse statewide. False legal green-lights.
7. **Stale/contradictory:** winter muzzleloader dates off ~2 weeks; two license-fee handlers
   contradict ($20 vs $35 resident); bear zone county list inconsistent AI-vs-data;
   `REGULATIONS_META.nextSeasonExpectedBy='2026-08-01'` so staleness banner won't fire until Aug.

## Meta-audit: what the audit process never checks (blind spots, ranked)

1. **Offline-first never tested with network OFF** — the mission's core word, the least-tested
   dimension. The 6-week silent backend death proves audits run online.
2. **Cold-start on clean install / real iPhone 12 never run** — 10-13 providers init at boot.
3. **Data factual accuracy never verified vs live DNR** — only "is there a handler," never "is it right."
4. **First-run / zero-data / empty states never audited** — every tap-through assumed existing data.
5. **Error-state UX deferred as "polish"** — swallowed failures in an offline field app.
6. **Real-device performance / memory / leaks never run** — 5 Mapbox screens, thousands of features.

### Recurring failure-modes (audit catches instances, not root causes)
- **Pattern A — config fixed, consumers not swept** (≥4×: email, ?code= URL, API_BASE_URL,
  inviteCode; same shape as the prod AASA outage). Fix: single-source-of-truth modules +
  a build-failing assertion on duplicate literals.
- **Pattern B — persistence load/save asymmetry** (≥2×, same context). Fix: one
  `createPersistedContext` primitive + a round-trip (write→reload→assert) test.

  off ~5 queries). Fix: doc-vs-reality assertions.
