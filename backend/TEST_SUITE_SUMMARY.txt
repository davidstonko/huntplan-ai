================================================================================
KEY DESIGN DECISIONS:
================================================================================

1. In-Memory SQLite
   - Rationale: Speed, isolation, no external dependencies
   - Tradeoff: Can't test complex PostgreSQL-specific features
   - Mitigation: Schema matches production (GeoJSON, JSONB → simulated)

2. Async-First
   - Rationale: Matches FastAPI async patterns
   - Implementation: All tests and fixtures are async
   - Benefit: Tests production-like code paths

3. Fixture-Based Setup
   - Rationale: DRY, reusable, composable
   - Example: test_camp_with_members builds on test_users + test_db_session
   - Benefit: Each test gets fresh, clean state

4. Class-Based Organization
   - Rationale: Clear test grouping (TestCreateCamp, TestListCamps, etc.)
   - Benefit: Easy to run related tests together
   - Example: pytest tests/test_deercamp.py::TestCreateCamp

5. Realistic Data
   - Rationale: Tests should reflect real usage
   - Examples: MD coordinates (39.2904, -76.6122), real hunter handles
   - Benefit: Catches edge cases in real data
