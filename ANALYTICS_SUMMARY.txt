KEY FEATURES
================================================================================

Crash Reporting Service:
  • Sentry integration with graceful SDK fallback
  • Error capture with context metadata
  • Breadcrumb tracking for debugging
  • Performance transaction monitoring
  • Privacy-first: no PII, anonymous device ID only
  • Environment detection (dev/staging/prod)
  • Scoped error reporting with withScope()

Analytics Service:
  • 8 event types: screen_view, feature_used, affiliate_tap, search,
    filter_change, plan_created, trip_planned, error
  • AsyncStorage-backed offline queue (max 500 events)
  • Auto-flush every 60 seconds
  • Batch submission to backend
  • Privacy: anonymous session ID + device ID only
  • Event queue inspection for debugging
  • Full lifecycle: enqueue → flush → clear

Backend Analytics API:
  • POST /api/v1/analytics/events — Batch event submission
  • GET /api/v1/analytics/summary — Event statistics
  • GET /api/v1/analytics/health — Service health check
  • Input validation (max 100 events per request)
  • Rate limiting via IP tracking (MVP)
  • In-memory event store (10k max)
  • Pydantic schema validation

API SPECIFICATION
================================================================================

Mobile → Backend:
  POST /api/v1/analytics/events
  
  Request: {
    "events": [
      {
        "id": "timestamp_random",
        "type": "screen_view|feature_used|affiliate_tap|...",
        "screenName": "MapScreen",
        "productName": "Gobstopper Decoy",
        "asin": "B0...",
        "category": "decoys",
        "timestamp": 1712750400000,
        "sessionId": "device-uuid",
        "appVersion": "2.1.0",
        "metadata": { ... }
      }
    ],
    "device_id": "device-uuid",
    "app_version": "2.1.0",
    "platform": "iOS"
  }

  Response: {
    "success": true,
    "events_received": 2,
    "message": "Received 2 events"
  }

Error Responses:
  400: Empty events, too many events (>100), malformed format
  429: Rate limit exceeded
  500: Server error

================================================================================
SUPPORT & TROUBLESHOOTING
================================================================================

Common Issues:

Q: Analytics not flushing?
A: Check network connectivity, verify backend /health endpoint, review console.

Q: Crash reporting not initializing?
A: If Sentry SDK not installed, service falls back to console logging.
   Verify DSN format: https://key@sentry.io/project-id

Q: Events stuck in queue?
A: Call flushEvents() manually, check AsyncStorage keys, review network logs.

Q: High event volume?
A: Reduce trackScreenView() calls, filter non-essential events, increase flushInterval.
